# V33 远征检查点实施与实验计划

**Goal:** 从已发布的 V32（013f9e8）继续，让远征可退出后续玩，并保证跨关卡资源与结算正确。

**Architecture:** 独立 `campaign_checkpoint.gd` 保存版本化的远征状态；两个轮换槽保留上一份有效记录，读取时校验摘要、结构和内容 ID，选取最新有效记录。主流程在开战前、通关后、节点选择后写入检查点；菜单显示继续入口与恢复位置。恢复战斗从本关起点重新开始，局内卡牌、敌人和弹道不保存；路线和未结算事件原地恢复。

**Tech Stack:** Godot 4.4.1 / GDScript / JSON / Windows x64。

## 实施范围

- [x] `game/scripts/campaign_checkpoint.gd`：保存编队、关卡、种子、路线、裂隙币、遗物、远征增益、关系、剧情标志和奖励去重记录；类型/版本/ID/数值校验先于任何状态变更；双槽损坏回退；错误可见。
- [x] `game/scripts/run/run_state.gd` 与 `campaign_node_resolver.gd`：远征幸运独立保留，下一关重新应用；局内卡牌强化仍清空。
- [x] `game/scripts/main.gd`：检查点生命周期、继续远征、通关路由恢复；失败与无尽不发战役奖励；构筑记录包含结算后的货币；自动化测试使用隔离目录。
- [x] `game/scripts/mode_select_panel.gd`：继续入口、关卡/队伍/资源摘要、恢复语义与错误提示；保留模式与设置入口。
- [x] `game/scripts/qa_v33.gd`：实际文件往返、类型污染/坏 JSON/未知版本/未知角色拒绝、单槽损坏回退、写失败、事件续玩、重领防护、幸运跨关、失败奖励、菜单点击与截图。
