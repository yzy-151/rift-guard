## 近战压力计时与拥堵验收

维持原单位上限：前期 80，后期 96，没有为了测试把人数提高到 100。使用三名高生命角色、60/80/96 个普通近战，按每秒 60 次更新；预热 120 帧，统计后续 240 帧的敌人更新耗时。槽位列为对应整批敌人的 `destination()` 分配/复查耗时均值，另取 30 轮。此处是 headless CPU 模拟计时，不能当作完整游戏渲染帧率。

| 场景 | 更新均值：修复前 → 最终 | 最终 P95 | 最终更新吞吐 | 槽位整批均值：修复前 → 最终 |
| --- | ---: | ---: | ---: | ---: |
| 60 怪站桩 | 13.486 → 5.754 ms | 8.895 ms | 173.8 次/秒 | 5.001 → 1.010 ms |
| 80 怪站桩 | 38.850 → 7.084 ms | 12.834 ms | 141.2 次/秒 | 24.977 → 1.706 ms |
| 96 怪站桩 | 62.392 → 9.219 ms | 17.253 ms | 108.5 次/秒 | 52.189 → 2.204 ms |
| 96 怪移动引怪 | 56.629 → 11.396 ms | 17.353 ms | 87.7 次/秒 | 32.536 → 2.066 ms |

发现的实际瓶颈是空位已满时，候位者仍每帧重新扫描所有候选和怪物。最终仅加入 0.30–0.57 秒的错峰复查、已站定短路和距离粗筛，保留八个前排槽位、外圈候位、人数上限及原测试断言。96 怪计时中最高单次更新约 31 ms，仍存在导航刷新等尖峰；未据此声称所有帧都能保持 60 FPS。

移动引怪时 71/96 怪发生至少 45 单位的有效追移。角色可以凭速度躲开近战，测试没有要求移动过程中必定受伤；停止移动后前排恢复有效攻击。站桩压力组均持续受到前排攻击，没有整群失去目标的现象。

首波夹具在真实第一关三条路线分别生成远程/近战混合队列，均抵达终点。隔墙用例采用与风蚀庭院同尺寸的断墙，三人站在墙的另一边：12 怪中 8 个先绕墙到达并攻击，前排被真实击杀后，其余 4 个全部绕墙补位，最终最小怪物间距 42.60。前排不死亡时后排会合理候位；不强迫后排穿过前排身体。

隔墙复核发现，过早在墙后预订攻击槽位并绕英雄画大弧会锁住墙角队列。最终只在绕墙后选择接敵侧，并将隔墙导航期间的绕行限制在近身范围；严格身体碰撞仍保留。临时尝试的穿过身体和额外让路算法未保留。最终重新执行 42 项间距、294 项模拟和 246 项经典回归，均为 0 失败。

## 独立整合复核

读取 `main.gd`、家园区域/探索/面板、无尽选择面板和音频事件接线；另在原生 OpenGL 窗口派发鼠标移动、按下和松开，取得 12 项断言、0 失败：

- 三张地图卡均选择准确的 `blood_gate`、`frost_isles`、`wind_cross`，随后进入阵容面板。
- 地图弹层可见时模拟时间不推进。
- 家园区域剧情阻止移动和战斗推进，进入对话保留区域及站位。

家园返回/存档流程另经只读检查：区域及已读场景单独持久化，剧情结束返回当前区域，访问区域不解锁战斗角色。本轮独立检查没有发现新的阻断问题。检查发现的无尽首发登场音频事件缺口已在模拟层修复，并由上述回归覆盖。
